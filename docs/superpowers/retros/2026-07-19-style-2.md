### S2. 9y9 discipline validated a failure mode — reviewer-spec fabricated a spec anchor URL

`mvu` reviewer-spec iter 1 proposed replacing a wrong anchor `#pseudo-pages` with `#page-pseudo-class`. Implementer's independent WebFetch (per 9y9 (c) — "reviewer-spec remit includes verifying primary source") found `#page-pseudo-class` does **not** exist on the CSS Paged Media L3 page; the real anchor is `#typedef-pseudo-page`. Reviewer's proposed anchor was **fabricated** (plausibly generated based on typical W3C spec anchor naming conventions, not verified against the actual TR).

A similar earlier fire: `#page-selectors-syntax` (from bd task filing) was accepted for several iters before implementer's WebFetch surfaced that the real anchor is `#syntax-page-selector`.

Root cause: 9y9 (c) ("reviewer-spec's remit explicitly includes verifying the task's own spec claims") reads the primary source when **evaluating** claims, but does not explicitly require WebFetch when **proposing** replacement anchors. The proposal side has been slipping into "fluent-generation from spec-naming intuition" rather than "verified-primary-source lookup".

Iter 2 of mvu's spec review self-noted: "reviewer-spec should treat spec anchors as first-class artifacts requiring WebFetch verification before proposing them. Consider a rule改善 line item: 'spec-anchor suggestions must be WebFetch-verified in the same iter that proposes them.'"

**Rule-improvement scope**: filed as bd decision D2 below — extension of 9y9 (c) to cover the **propose-side** of anchor citations, not just the evaluate-side. Companion 9y9 already applied for task-authoring flavor; this closes the reviewer-authoring flavor of the same discipline.
