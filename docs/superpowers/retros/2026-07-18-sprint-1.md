## Signals (5)

### S1. `cargo fmt` / `clippy` drift accumulator — repeat offender

Sprint 1 spent **1 spun-out task (5ta)** cleaning up pre-existing `cargo fmt`
drift that accumulated across the `e93` / `37c` / `87x` merges immediately
before sprint start. This is not a new problem:

- Existing open issue `raikiri-spike-rcf` (created 2026-07-16, P3, `wall/build`
  label) documents the same drift with an explicit remediation plan
  (workspace fmt commit + CI gate).
- One sprint earlier (base `be1cfce`), `87x` was spun out to clean
  `clippy::collapsible_if` drift from the `e93` merge — same shape.

Pattern: **gate.md §8.1 correctly forces cleanup at the NEXT task's gate**,
but each successive task pays the spin-out cost because merge-time does not
enforce workspace-wide `cargo fmt --check` / `cargo clippy -D warnings` before
the merge commit is created.

Cost per occurrence: ~1 task worth of coordinator + implementer time (small
individually, but N tasks between now and rcf claim = N × 1 spin-out).

### S2. Parallel-session duplicate work on shared debt

`5ta` and `61t` ran in parallel sessions. Both coordinators independently
detected the fmt drift; `61t`'s coordinator produced a redundant fmt commit
(`95cb09b`) because it had no way to know that `5ta` was already claimed to
fix the same shared debt. git merged the two cleanly, but the effort was
duplicated.

`bd claim` prevents double-claim on named issues; **shared repo-hygiene debt
that surfaces mid-gate has no coordination primitive** — the first coordinator
to spin out an issue "wins" the fix, and other parallel sessions must poll
`bd ready` to notice.

### S3. Positive: lens-matrix trivial row fit is confirmed

Both `dtl` (attribute-only derive-Debug change) and `61t` (2-line constant
replace) matched lens-matrix's `trivial` row and fired **only the quality
lens**. Both went through the 3-stage gate cleanly with 0 findings. `5ta`
(fmt-only mechanical diff) also matched the trivial row.

**Rule fit**: trivial row is correctly scoped. No rule change proposed.

### S4. Positive: 3-stage autonomous gate delivers 100% autonomous merge

All 3 tasks merged without a `blocked/human` label. `codex:rescue` final review
returned 0 findings on all 3, consistent with the trivial scope. No `advisor()`
calls needed. The gate is not over-fitted to trivial scope, but sprint 1 does
not stress the gate on non-trivial scope — that is deferred to future sprints.

### S5. Stale worktree accumulation (out-of-sprint, discipline hint)

`git worktree list` shows 6 `wf_70528a1a-718-*` worktrees from an older
session that survived sprint 1's coordinator cleanup (coordinator cleans up
its OWN worktrees on merge, not stale ones from prior sessions). Not a
sprint-1 defect, but a discipline hint: `git worktree prune` should be part
of sprint-close hygiene, either at coordinator sprint-drain or at retro time.
