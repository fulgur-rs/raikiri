# m1.22 M1.4a impl — Minimal UA Stylesheet + Cascade Origin — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** raikiri-html bundle した minimal UA CSS (`html, body, div, p, h1-h6 { display: block }`) が Document 経由で cascade に届き、author style 無しの `<p>` が `display: Block` として computed される。同時に `Origin::UserAgent < Author` の origin precedence を cascade path に反映し、`!important` UA が `!important` Author を上書きする挙動を成立させる。

**Architecture:** blitz の `HtmlDocument::add_user_agent_stylesheet` 相当を raikiri の crate 責務にマップし直し、`Document` (raikiri-dom) が stylesheets を保有する。parse() 時に既定 UA CSS + Consumer 提供 extra_stylesheets を Document に注入。cascade phase は Document.stylesheets を iterate して RuleTree に流し込む。Origin enum は raikiri-style 内部、`StylesheetKind` (raikiri-traits) が DOM 側の shared vocabulary。cascade tuple は `(rank, specificity, source_order)` に変更、`rank = cascade_rank(origin, important)` で CSS Cascading L4 §6.4.4 の !important 反転扱いを表現。

**Tech Stack:** Rust 2024 edition、rust-version 1.89.0、cssparser 0.37、selectors 0.39、smol_str 0.3、std::borrow::Cow、既存 workspace deps のみ (新規 crate 依存追加なし)。

## Global Constraints

- 対象 crate: `crates/raikiri-traits` (StylesheetKind)、`crates/raikiri-dom` (Document 拡張)、`crates/raikiri-html` (MINIMAL_UA_CSS + parse 注入)、`crates/raikiri-style` (Origin + DisplayValue + inherit_from + rank 化)

```rust
    // ─── stylesheets (M1.4a、raikiri-spike-m1.22) ───────────────────

    /// Stylesheet を Document に associate する。
    ///
    /// - lazy: parse は行わない。cascade phase で一括処理される。
    /// - 呼び出し順で同一 `kind` 内の cascade source_order が決まる
    ///   (spec §M1.4a)。
    /// - `Cow<'static, str>` により、bundled UA CSS 等 static &str は
    ///   borrow のまま保持され allocation なし。Consumer 提供の
    ///   `String` は Cow::Owned で消費される。
    pub fn add_stylesheet(
        &mut self,
        source: impl Into<Cow<'static, str>>,
        kind: StylesheetKind,
    ) {
        self.stylesheets.push((source.into(), kind));
    }

    /// 現在 associate されている全 stylesheet を `(source, kind)` の
    /// tuple として iterate する。順序は `add_stylesheet` の呼び出し順。
    ///
    /// cascade orchestrator (raikiri umbrella) が RuleTree 構築時に
    /// consume する想定。
    pub fn stylesheets(&self) -> impl Iterator<Item = (&str, StylesheetKind)> + '_ {
        self.stylesheets.iter().map(|(cow, kind)| (cow.as_ref(), *kind))
    }
```

fn pick_winners(
    candidates: &[(PropertyValue, bool, Origin, Specificity, u32)],
) -> HashMap<PropertyKey, PropertyValue> {
    // best entry: (rank, spec, source_order, value)
    let mut best: HashMap<PropertyKey, (u8, Specificity, u32, PropertyValue)> = HashMap::new();

    for (value, important, origin, spec, order) in candidates {
        let rank = cascade_rank(*origin, *important);
        let key = value.key();
        let candidate = (rank, *spec, *order, value.clone());
        match best.get(&key) {

                    best.insert(key, candidate);
                }
            }
            None => {
                best.insert(key, candidate);
            }
        }
    }

fn beats(
    candidate: &(u8, Specificity, u32, PropertyValue),
    existing: &(u8, Specificity, u32, PropertyValue),
) -> bool {
    // Tuple compare: (rank, specificity, source_order)
    // - rank 高い方が勝つ (Important UA > Important Author > Normal Author > Normal UA)
    // - 同 rank なら specificity 高い方が勝つ

    // 意図的。cross-rule では source_order が異なるので `>=` でも安全。
    (candidate.0, candidate.1, candidate.2) >= (existing.0, existing.1, existing.2)
}
