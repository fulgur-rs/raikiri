# m1.14 hello-world-vrt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `raikiri::html_to_png<R: Read>(input: R) -> Result<Vec<u8>, RenderError>` を実装し、`<p style="color:red">Hi</p>` を A4 1 ページ PNG に raster する end-to-end pipeline と、`tests/reference/hello-world/` fixture + integration test を pin する (spec §M1 acceptance の "hello-world VRT pass" を成立させる)。

**Architecture:** `raikiri` umbrella crate 内に新規 `html_to_png.rs` module を追加し、既存 `parse_html` → `raikiri_dom::layout_single_page` → `raikiri_paint::paint_single_page` → `anyrender::render_to_buffer<VelloCpuImageRenderer>` → `raikiri_vrt::encode_png` の 5 stage pipeline を chain する。`HtmlDocument` の `pub(crate)` field を split-borrow して `layout_single_page(&mut dom, &cascade, ...)` を呼ぶことで accessor 追加を回避する。fixture は crate-local (`crates/raikiri/tests/reference/hello-world/`) に配置し、`raikiri_vrt::reference::run_and_compare` の diff artifact root と同じ crate manifest 下で完結させる。

**Tech Stack:** Rust 2024 edition (rust-version 1.89)、anyrender 0.11、anyrender_vello_cpu 0.14 (multithreading feature)、tiny-skia 0.11 (raikiri-vrt 経由の PNG encode)、既存 raikiri-{traits, dom, html, paint, vrt} workspace crate。

## Global Constraints

- Rust edition 2024、rust-version 1.89.0 (workspace 定義)
- 全 workspace の warnings-as-errors 適用 (`cargo clippy --all-targets -- -D warnings`)
- `#[allow(clippy::result_large_err)]` を `html_to_png` に付与 (既存 `parse_html` と同じ理由、`RenderError` が variant 大きめ)
- PageBox は M1 では `PageBox::A4` 固定 (spec §M1.6)、custom PageBox 対応は M2+ で `html_to_png_with(...)` variant として追加予定
- Fixture 配置は crate-local `crates/raikiri/tests/reference/hello-world/` (spec §M1 の `tests/reference/hello-world/` を name-space 意図と解釈)
- Tier 1 platform = Linux x86_64 で pixel-exact 比較 (`Tolerance::EXACT`、spec §12.7 / §5.2)
- Determinism (10 連続 byte-identical) は m1.13 に委譲、本 issue は 3 連続 md5 一致の smoke check のみ
- 既存 test regression 禁止: `stubs.rs` の `render_streaming_returns_unimplemented_with_feature_name` は `migration_hint.contains("html_to_png")` を pin しているので特に注意

- [ ] **Step 3: 本実装に差し替え**

`crates/raikiri/src/html_to_png.rs` の `pub fn html_to_png` body を差し替え、上部 `use` も追加:
```rust
use anyrender::render_to_buffer;
use anyrender_vello_cpu::VelloCpuImageRenderer;
use raikiri_html::ParseOptions;
use raikiri_traits::{PageBox, RenderError};
use raikiri_vrt::encode_png;

use crate::parse::parse_html;

// ...doc comment 既存...
#[allow(clippy::result_large_err)]
pub fn html_to_png<R: std::io::Read>(input: R) -> Result<Vec<u8>, RenderError> {
    // ParseOptions は default 相当 (M1 fixture は extra stylesheet / network / base_url 不要)
    let opts = ParseOptions {
        extra_stylesheets: &[],
        network: None,
        base_url: None,
    };
    let mut doc = parse_html(input, &opts)?;

    let page_box = PageBox::A4;
    // pub(crate) field を crate-internal から split-borrow。accessor 経由だと
    // `&mut self` が要求されて cascade への同時参照が壊れるが、field 直接なら OK。
    // `?` は raikiri-traits の `From<LayoutError> for RenderError` (error.rs:137-140)
    // で LayoutError → RenderError::Layout に自動変換される。
    raikiri_dom::layout_single_page(&mut doc.uncascaded.dom, &doc.cascade, page_box)?;

    // PageBox = 793.7008 × 1122.5197 CSS px → 794 × 1123 u32 buffer
    let width = page_box.width.ceil() as u32;
    let height = page_box.height.ceil() as u32;

    // paint_single_page への split-borrow (dom / cascade は render_to_buffer の
    // closure に move されないよう `let` binding で外に出す)
    let dom = &doc.uncascaded.dom;
    let cascade = &doc.cascade;
    let rgba = render_to_buffer::<VelloCpuImageRenderer, _>(
        |scene| raikiri_paint::paint_single_page(scene, dom, cascade, page_box),
        width,
        height,
    );

    Ok(encode_png(&rgba, width, height))
}
```

## Notes for the Implementer

**Split-borrow ハマりどころ**: `parse_html` 直後の `let mut doc = ...` は必須 (`mut` を落とすと `layout_single_page(&mut doc.uncascaded.dom, ...)` が borrow-check で NG)。cascade は `&doc.cascade` で immutable、dom は `&mut doc.uncascaded.dom` で mutable — Rust の split-borrow rule で **同時に取れる** のは各 field を直接 project する場合のみで、accessor method 経由だと `self` 全体を borrow するので不可。この差が html_to_png design で `dom_mut()` accessor を追加せずに済んでいる理由。

**paint closure の move**: `render_to_buffer::<R, _>(closure, w, h)` の closure は `FnOnce(&mut R::ScenePainter<'_>)`。`dom` / `cascade` を closure 内で参照すると Rust は capture kind を推論する時に「closure が値を borrow で captured」と判断するが、closure が渡された時点で `render_to_buffer` に move される。ここで `dom = &doc.uncascaded.dom` の `let` binding を closure の外で作っておくと `&Document: Copy` (実際は `&T: Copy` for any T) のおかげで closure がその reference を copy-capture するので、`doc` を後で drop 順に困らない。raikiri-vrt tests の `#[allow(clippy::redundant_closure)]` パターンは HRTB inference の都合で必須。

**Golden 生成の race**: `RAIKIRI_UPDATE_GOLDENS=1` は `libtest` の parallel 実行下で他 test の env と race する可能性があるが、m1.14 は integration test binary が 1 test しか持たないので実質 single-threaded で走る。m1.13 (determinism-test) で複数 test を並列に持つ場合は m1.10 の `EnvGuard` pattern が必要になるが、本 task では不要。

**Fixture の 27 bytes 内訳**: `<p style="color:red">Hi</p>` = `<`(1) + `p`(1) + ` `(1) + `style="color:red"`(17) + `>`(1) + `Hi`(2) + `</p>`(4) = 27。改行を末尾に付けると 28 bytes になり、html5ever は同じ結果を produces する (last-line trailing whitespace は tree に反映されない) が、fixture size は 27 bytes で pin する (`printf` は改行を付けない)。
